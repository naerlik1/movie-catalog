# Каталог фильмов — вариант 25

Учебный проект на Django REST Framework и React. В каталоге можно найти фильм, посмотреть средний рейтинг, оставить отзыв и добавить фильм в избранное. Фильмы и постеры добавляет администратор. Backend написан на классах: `APIView`, `ListCreateAPIView`, `RetrieveUpdateDestroyAPIView`, классы сериализаторов, моделей и разрешений.

Стек: Python 3.12, Django 5.2, DRF, Simple JWT, PostgreSQL 16 / psycopg 3, React 18, Vite, React Router 6, nginx, gunicorn, Docker Compose. SQLite не используется.

Исходники: [naerlik1/movie-catalog](https://github.com/naerlik1/movie-catalog). Опубликованные Docker-образы: [backend](https://hub.docker.com/r/naerlik/movie-catalog-backend) и [frontend](https://hub.docker.com/r/naerlik/movie-catalog-frontend), тег `1.0`, архитектуры AMD64 и ARM64. Команды запуска готовых образов и их контрольные суммы — в [docs/PUBLICATION.md](docs/PUBLICATION.md).

## Быстрый запуск на этом MacBook

В корне проекта есть три файла для двойного щелчка в Finder:

- **`Запустить.command`** — запускает Docker Desktop при необходимости, поднимает контейнеры, ждёт готовности БД и приложения, открывает каталог в браузере.
- **`Остановить.command`** — останавливает проект с сохранением базы и постеров.
- **`Обновить сборку.command`** — пересобирает изменённый код и запускает новую версию.

Обычный повторный запуск использует уже скачанные Docker-образы и не требует доступа к реестру. Первая сборка и обновление зависимостей требуют интернета. Устанавливать Python, Node.js или PostgreSQL непосредственно на Mac не нужно: они находятся в Docker. Демо-аккаунты и данные на этом Mac уже созданы.

Скрипты сами находят Docker внутри `/Applications/Docker.app`, даже если команда `docker` не добавлена в PATH. Имеющийся `.env` не перезаписывается, данные автоматически не сбрасываются. Подробности: [docs/MACBOOK.md](docs/MACBOOK.md).

## Запуск

Установите Docker Desktop (Windows/macOS) или Docker Engine с Compose (Ubuntu). Выполняйте команды из корня проекта.

```bash
cp .env.example .env
```

В `.env` заполните `DJANGO_SECRET_KEY` и `DB_PASSWORD` случайными строками. Например, для каждого значения отдельно выполните `openssl rand -hex 32`. В репозитории `.env` не хранится. Для этого локального экземпляра он уже создан.

```bash
docker compose up -d --build
docker compose ps
curl http://localhost:8084/health
```

Открыть: **http://localhost:8084**. Миграции и сбор статики запускаются автоматически перед gunicorn. Обычная регистрация всегда создаёт пользователя без административных прав.

Для пустой базы можно создать администратора:

```bash
docker compose exec app python manage.py createsuperuser
```

Либо один раз заполнить базу демонстрационными данными:

```bash
docker compose exec app python manage.py seed_demo
```

Команда попросит два пароля скрытым вводом, создаст администратора, пользователя, 14 фильмов, отзывы, избранное и собственные учебные обложки. Повторный запуск не меняет существующие данные и пароли. Официальные постеры не используются.

| Роль | Email | Пароль |
| --- | --- | --- |

При запуске `seed_demo` на новой машине введите эти демонстрационные пароли, если хотите использовать ту же таблицу; для опубликованного экземпляра задайте свои и обновите тестовый доступ перед сдачей.

## Что доступно

- Гость читает общий каталог, карточки и отзывы, регистрируется и входит.
- Пользователь отмечает просмотренные фильмы, оставляет по одному отзыву после просмотра, меняет и удаляет только свой отзыв, ведёт собственное избранное.
- Администратор создаёт фильмы, изменяет и удаляет только добавленные им фильмы и постеры. Общий каталог доступен всем администраторам для чтения.
- Поиск по названию и описанию обновляется во время ввода с задержкой 300 мс. Кнопка «Найти» также работает. Есть фильтры года и минимального среднего рейтинга, сортировка и пагинация по 12 записей.
- Отметка «Просмотрен» принадлежит конкретному пользователю. API проверяет её перед созданием и изменением отзыва. Снять отметку можно после удаления своего отзыва; автоматически отзывы не удаляются. Для существующих отзывов миграция добавляет отметки просмотра.
- Средняя оценка вычисляется через `AVG` отзывов при чтении, поэтому после добавления, изменения и удаления оценки сразу актуальны. Без отзывов возвращается `null`, а не ноль.
- JWT действует 24 часа. Токен хранится в `sessionStorage` и отправляется как `Authorization: Bearer ...`. Выход удаляет его из браузера и отзывает на сервере: старый токен тоже получает 401.
- Не более 10 попыток входа в минуту с одного IP. nginx перезаписывает `X-Forwarded-For`; gunicorn работает с одним sync worker, поэтому лимит не разделяется между процессами.
- Постеры JPG/PNG/WEBP до 5 МБ проверяются по расширению, заявленному MIME и содержимому Pillow. Имена с путями отклоняются. Ответы: 415 — неверный тип, 413 — превышен размер.
- Файл хранится как `uploads/public/<UUID>.<расширение>`, метаданные — в таблице `files`. Замена удаляет старый файл; удаление фильма удаляет постер, отзывы и отметки в избранном.
- Ошибки API: `{"errors": {"поле": "сообщение"}}`. React показывает их возле полей. Значения выводятся через стандартное экранирование React, SQL-запросы — через ORM.

### Как совмещены общие правила и вариант 25

Специальное правило «фильмы добавляет админ» имеет приоритет над общим CRUD для обычного пользователя. Чужой фильм можно читать в публичном каталоге, но нельзя изменять. Чужие отзывы тоже публичны, но их изменение и удаление запрещены; чужое избранное недоступно.

По уточнению преподавателя обычный пользователь не добавляет собственные фильмы. Он читает каталог, отмечает просмотренные фильмы, оставляет отзывы и ведёт личное избранное. Раздел «Мои записи» доступен только администратору: там фильмы, которые добавил он сам.

У обычного пользователя кнопка «Скачать Excel» находится только в разделе «Избранное». В файл входят только его избранные фильмы. Сервер применяет это ограничение даже при прямом запросе к API или подмене `scope=all`. Администратор может выгружать общий каталог, свои записи или своё избранное. Поиск, фильтры и сортировка повторяются в Excel; пагинация не ограничивает выгрузку. Уточнение преподавателя снимает прежнюю неоднозначность общего правила экспорта для варианта 25.

## Excel

`GET /api/movies/export/` возвращает `movies_ГГГГ-ММ-ДД.xlsx` с листом «Данные». В книге: жирные заголовки, закреплённая первая строка, автофильтр, ширина колонок по содержимому. ID, год, рейтинг и число отзывов — числа; даты — даты с форматом `DD.MM.YYYY`. Названия, описания и имена файлов с начальным `=`, `+`, `-`, `@` получают апостроф. Файл создаётся в памяти. Более 10 000 строк — ошибка с предложением уточнить фильтры, без незаметного обрезания. Лист «Сводка» для варианта 25 в задании не требуется.

## API

У путей нет завершающего `/`, кроме `/api/movies/export/`, как в задании. Формат — JSON, загрузка файла — `multipart/form-data`, поле `file`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/auth/register` | Регистрация: username, email, password, password_confirm |
| POST | `/api/auth/login` | Вход по email и паролю, JWT и безопасные данные пользователя |
| POST | `/api/auth/logout` | Отзыв текущего JWT |
| GET | `/api/auth/me` | Текущий пользователь |
| GET, POST | `/api/movies` | Список / создание фильма администратором |
| GET, PUT, PATCH, DELETE | `/api/movies/:id` | Карточка / изменение и удаление владельцем-администратором |
| GET | `/api/movies/export/` | Выгрузка Excel для вошедшего пользователя |
| POST | `/api/movies/:id/files` | Добавление или замена постера владельцем |
| DELETE | `/api/files/:id` | Удаление постера владельцем |
| GET, POST | `/api/movies/:id/reviews` | Публичные отзывы / новый отзыв вошедшего пользователя |
| GET | `/api/movies/:id/my-review` | Только собственный отзыв; 204, если его ещё нет |
| GET, PUT, PATCH, DELETE | `/api/reviews/:id` | Собственный отзыв |
| POST, DELETE | `/api/movies/:id/favorite` | Добавление / удаление только в своём избранном |
| POST, DELETE | `/api/movies/:id/watched` | Личная отметка просмотра / снятие, если нет своего отзыва |
| GET | `/health` | Проверка приложения и соединения с БД |

Параметры списка и экспорта: `search`, `year`, `rating_min`, `scope=all|mine|favorites`, `ordering=newest|title|year|rating`. Параметры списка: `page`, `limit` (максимум 100). Ответ списка: `count`, `next`, `previous`, `results`.

Год фильма: 1888 — текущий год; название после обрезки пробелов 1–120 символов; описание до 2000 символов. Отзыв: целая оценка 1–10 и непустой текст до 2000 символов. Email уникален без учёта регистра, username — 3–30 символов латиницы, цифр и `_`; пароль — 8–64 символа, хотя бы буква и цифра. Уникальность отзывов, избранного и отметок просмотра закреплена ограничениями БД.

## Проверки

```bash
docker compose exec app python manage.py check
docker compose exec app python manage.py makemigrations --check --dry-run
docker compose exec app python manage.py test --noinput
```

Тесты используют настоящую PostgreSQL и отдельную временную тестовую БД. Покрыты регистрация, повторный email в другом регистре, JWT и выход, лимит входа, права администратора и владельца, CRUD, повторный отзыв, пересчёт рейтинга, личное избранное и просмотренные фильмы, запрет отзыва до просмотра, поиск и пагинация, постеры и удаление с диска, состав Excel, типы ячеек, защита формул и лимит экспорта.

После `docker compose restart` данные хранятся в томах `pgdata` и `uploads`. Команда `docker compose down` сохраняет тома. **`docker compose down -v` удаляет их вместе с данными.**

## Деплой на Ubuntu Server

Подробная последовательность и команды публикации образов: [docs/DEPLOY.md](docs/DEPLOY.md). Ubuntu 22.04/24.04, минимум 2 vCPU, 2 ГБ RAM, 20 ГБ диска; Bridge-сеть или корректный проброс порта **8084**. Внешний порт только у nginx; PostgreSQL и Django наружу не публикуются.

На VM заполните `DJANGO_ALLOWED_HOSTS` (включая IP виртуальной машины, `localhost`, `127.0.0.1`, `app`) и `CSRF_TRUSTED_ORIGINS=http://IP_VM:8084`. С другого компьютера приложение открывается по `http://IP_VM:8084`. Секреты и пароль БД задайте до первого старта; смена переменной `DB_PASSWORD` не меняет пароль в уже созданной PostgreSQL.
