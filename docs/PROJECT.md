# Как объяснить проект на защите

Для начала с нуля откройте [QUESTIONS.md](QUESTIONS.md). Пошаговый показ — в [DEFENSE.md](DEFENSE.md), короткая памятка — в [CHEATSHEET.md](CHEATSHEET.md). Ниже разобраны механизмы проекта по коду.

## Путь запроса

Браузер загружает React из nginx на порту 8084. React вызывает `fetch('/api/...')`. nginx передаёт запрос Django на внутренний порт 8000. Django проверяет JWT, права, данные и выполняет запрос через ORM в PostgreSQL. Ответ возвращается JSON. React обновляет страницу без полной перезагрузки.

Постеры nginx читает из общего тома. Backend записывает их в `/app/uploads/public`, frontend-контейнер видит этот том только для чтения. Сами файлы в PostgreSQL не записываются — там только имя, MIME, размер и связь с фильмом.

## Почему классы

`MovieListCreateView` наследует `ListCreateAPIView`: GET выдаёт список, POST создаёт фильм. В `get_queryset` подключаются фильтры и рейтинг, в `perform_create` ставится текущий владелец. `MovieDetailView` наследует `RetrieveUpdateDestroyAPIView` и обрабатывает GET, PUT/PATCH, DELETE для одного объекта.

`MoviePermission` проверяет роль и владельца на сервере. Скрытая кнопка в React нужна только для удобства: отправка запроса вручную не обходит проверку Django.

Для действий вроде выхода, избранного или Excel используется обычный `APIView`, потому что это не стандартное CRUD одной модели. Сериализаторы тоже классы: проверяют поля и определяют, какие данные попадут в JSON.

## Таблицы

- `users`: Django AbstractUser с уникальным email, коротким username и ролью через `is_staff`. `is_staff=True` означает admin в API. Пароль — штатный Django-хеш; `date_joined` выдаётся как `created_at`.
- `movies`: название, год, описание, владелец и даты создания/обновления.
- `files`: один постер на фильм, оригинальное и сохранённое имя, MIME, размер и дата. Обратная связь называется `poster`.
- `movies_review`: фильм, автор, оценка, текст, даты. Пара movie+owner уникальна.
- `movies_favorite`: фильм, пользователь, дата. Пара movie+owner уникальна.
- `movies_watched`: просмотренный фильм, пользователь, дата. Пара movie+owner уникальна; отметка личная.
- `accounts_revokedtoken`: идентификатор и срок действия токена, отозванного при выходе.

В ORM у связей стоит `on_delete=CASCADE`: при удалении Django удаляет зависимые записи. Signal `post_delete` откладывает удаление физического файла до успешного commit, чтобы откат транзакции не оставил ссылку на уже удалённую картинку.

## Отзывы и рейтинг

Рейтинг не хранится отдельным числом в Movie. ORM добавляет `Avg('reviews__rating')` при чтении. Поэтому редактирование и удаление отзыва не требуют отдельного сигнала пересчёта, и сохранённое среднее не может устареть.

Уникальность отзыва проверяется дважды: сначала понятная ошибка в API, затем уникальное ограничение в БД для одновременных запросов. Оценка 1–10 проверяется сериализатором, валидаторами модели и CHECK-ограничением.

По дополнительному требованию пользователя отзыв можно оставить только после отметки просмотра. Класс `WatchedView` добавляет и снимает личную отметку, а `ReviewListCreateView` и `ReviewDetailView` проверяют её на сервере. Клиент показывает форму только после отметки. При наличии собственного отзыва снять отметку нельзя, пока отзыв не удалён. Миграция `0002_watched` добавляет отметки к уже существующим отзывам без изменения их текста и оценки.

## Поиск во время ввода

В `CatalogPage` обычный `useEffect` ставит `setTimeout` на 300 мс. Если за это время введён следующий символ, `clearTimeout` отменяет предыдущий таймер. После паузы обновляется параметр `search` в URL, сбрасывается страница пагинации и выполняется тот же запрос API, что и при нажатии «Найти». Новые библиотеки для этого не нужны. Excel получает уже применённый поисковый запрос; пока текст ещё ожидает применения, кнопка экспорта отключена.

## Авторизация

При входе сервер сравнивает пароль через Django `authenticate`, создаёт JWT на 24 часа и возвращает только безопасные поля пользователя. React хранит JWT в `sessionStorage` и добавляет его в заголовок. При выходе клиент удаляет токен, сервер запоминает его `jti`; повторное использование получает 401.

Лимит входа учитывает IP. nginx удаляет возможную подмену `X-Forwarded-For`, а приложение доверяет одному прокси. В этой простой учебной конфигурации один sync worker и LocMemCache. При переходе на несколько workers кэш лимита нужно вынести в общее хранилище.

## Загрузка постера

Сначала проверяются права, затем размер, расширение, MIME и чтение изображения через Pillow. Исходное имя сохраняется в БД, а физический файл получает UUID. В транзакции блокируется строка фильма, удаляется прежняя запись постера и создаётся новая. При неудаче новый файл удаляется.

## Экспорт

Список и выгрузка используют одну функцию `filtered_movies`. По уточнению преподавателя обычный пользователь скачивает Excel только в разделе «Избранное». Сервер дополнительно фильтрует queryset по `is_favorite=True`: этот признак вычислен через `Favorite` именно текущего пользователя. Поэтому прямой запрос или подмена `scope=all` не выгрузят чужое избранное и фильмы вне своей подборки. Администратору разрешена выгрузка общего каталога. openpyxl собирает книгу в BytesIO. Числа остаются числами, даты — датами. Префикс-апостроф защищает Excel от формул из пользовательского текста.

## Что показать преподавателю

1. Гостевой каталог и ошибки регистрации на неверных данных.
2. Вход пользователя, добавление в избранное, отметка просмотра, отзыв, изменение оценки и обновление рейтинга. На другом фильме показать, что до отметки форма отзыва закрыта.
3. Второй пользователь не видит чужое избранное и не может изменить чужой отзыв по API.
4. Администратор добавляет фильм и постер, изменяет запись, скачивает Excel с фильтром.
   Обычный пользователь скачивает свою подборку из раздела «Избранное»; в общем каталоге у него кнопки выгрузки нет.
5. Удаление фильма с подтверждением, удаление зависимого постера, restart контейнеров и сохранность остальных данных.
6. В SSH Ubuntu показать `docker compose ps` с тремя сервисами, `/health` и опубликованные образы. При настроенном NAT другой компьютер открывает IP Mac:8084; этот порт проброшен в VM.
7. Если требуется, выполнить `sudo reboot` внутри Ubuntu, показать новый boot_id, автоматическое восстановление сайта и сохранённые записи с постерами.
